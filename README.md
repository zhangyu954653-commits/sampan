> **Sampan** = 舢板 = เรือสำปั้น
>
> 英文、中文、泰语里都有的一个词——一个不用翻译的词。
> 翻译（translate）的本义就是"渡过去"：一叶小船，把意思渡到对岸。

在钉钉/腾讯会议/Zoom 开会时，自动把**你说的中文翻成泰语**、**对方说的泰语翻成中文**（对方说中文也会翻成泰语）。
字幕显示在一个网页里，你把这个窗口共享出去，双方都能看到。

```
  你的麦克风 ───┐                              ┌─→ 自动判断是中文还是泰语
                ├─→ 断句 ─→ 语音识别 ─→ Claude 翻译 ─→ 网页大字幕
  钉钉里的声音 ─┘   (VAD)                      └─→ 中→泰 / 泰→中
```

**关键点：对方的声音是直接从电脑扬声器输出里抓的（WASAPI 环回），不用装虚拟声卡，也不用把手机放在麦克风前面。**

## 一、安装

**下载**：到 [Releases](../../releases/latest) 下载最新的 `Sampan-vX.Y.Z-Windows.zip`，解压到任意文件夹。

**第一次用**：先装 [Python 3.11](https://www.python.org/downloads/release/python-3119/)（**务必勾选 `Add python.exe to PATH`**），再双击 `启动.bat`，它会自动建环境装依赖，约 5~15 分钟。

**已经装好的电脑**（Python + 全部依赖 + Whisper small 模型都在本地）：直接双击 `启动.bat` 即可。

## 二、配置 API Key

第一次运行会在同目录生成 `config.json`，用记事本打开修改。

### 翻译（必填）—— Anthropic API Key

1. 打开 https://console.anthropic.com/ 注册账号
2. 左侧 **Billing** → 充值（最低 $5，够用很久）
3. 左侧 **API Keys** → **Create Key** → 复制出来的 `sk-ant-...`
4. 填进 `config.json`：

```json
"anthropic_api_key": "sk-ant-api03-你的key",
```

> **注册需要境外手机号 + 境外信用卡。** 如果办不了，用国内中转服务（搜「Claude API 中转」），拿到中转地址和 key 后这样填：
> ```json
> "anthropic_api_key": "中转给你的key",
> "anthropic_base_url": "https://中转商给的地址",
> ```

**费用**：默认用 `claude-sonnet-5`，一小时会议大约 **¥6~7**（按每句约 530 输入 + 40 输出 token、
一小时约 600 句估算）。想省一半，把 `"model"` 改成 `"claude-haiku-4-5"`，约 ¥3/小时，
而且快约 35%；代价是短句偶尔偏生硬。

> 模型 ID **不要加日期后缀**。写 `claude-haiku-4-5`，不是 `claude-haiku-4-5-20251001`。

### 语音识别（二选一）

**腾讯云免费额度**：一句话识别每月免费 **5000 次调用**（每月 1 号重置，不是一次性试用）。
一句话 = 一次调用，一小时会议约 660 次，所以**每月约 7.5 小时会议是免费的**。
超出后 ¥3.2/千次 ≈ ¥2.1/小时。

程序每分钟和退出时都会打印本次已调用多少次。想看账户总用量：
腾讯云控制台 → 费用中心 → 用量统计。

**方案 A：云端 Whisper（泰语最准）**

去 https://platform.openai.com/api-keys 拿 key，填进去：

```json
"asr": { "backend": "openai", "openai_api_key": "sk-..." }
```

费用约 ¥2.6/小时。

**方案 B：本地识别（免费、离线、不需要任何 key）** ← 当前就是这个

配置文件默认写的是 `"backend": "openai"`，但**没填 OpenAI Key 时程序会自动退回本地模型**，
所以只有 Anthropic Key 也能直接用，什么都不用改。

本机实测数据（i5-13500H，CPU，8 线程）：

| 转写模型 | 每句耗时 | 实时倍率 | 泰语精度 | 结论 |
|---|---|---|---|---|
| **small**（当前） | 4.5s | 0.97x | 会掉字母 | 唯一可用 |
| medium | 11.8s | 0.37x | 明显更好 | **不可用**，比说话还慢 3 倍，会无限积压 |
| 云端 Whisper | 约 1~2s | 远超实时 | 接近完美 | 需要 OpenAI Key |

语种判定由 `tiny` 模型专职负责（0.5 秒，实测 5/5 准确）。这比让 small 自己用
`language=None` 判快得多——实测 small 自动判语种要 7.0 秒，而 tiny 判 + small
按结果转写只要 4.4 秒。

> **模型下载卡住怎么办**：HuggingFace 新的 xet 下载后端在国内经常卡在几 MB 不动。
> 程序已经默认关掉它了。如果还是慢，在终端里先执行下面这句再启动：
> ```bash
> set HF_ENDPOINT=https://hf-mirror.com
> ```

> 没填 OpenAI key 时程序会**自动退回本地模式**，不会崩。

### 说话人性别（建议填，泰语必需）

泰语的第一人称和句尾敬语**分男女**，不填的话每句可能变来变去：

```json
"speaker_gender": "male",
```

- `"male"` → 一律用 `ผม` / `ครับ`
- `"female"` → 一律用 `ดิฉัน` / `ค่ะ`
- `""` → 用中性说法 `เรา` / `ครับ`

### 为什么同一句话有时译法不同

当前这代模型的 API **已经不再支持 `temperature` 参数**，无法强制输出固定不变。
程序用两个办法缓解：

1. **短句缓存**：28 字以内的句子翻过一次就记住，会议里重复说的"好的""能听到吗"
   保证每次译法完全一样（也省钱省时间）。缓存只存在于本次运行，重启就清空。
   长句不缓存——它们基本不会一字不差地重复，而且更依赖上下文。
   想调整门槛改 `cache_max_chars`。
2. **提示词里钉死风格**：强制口语（禁止"สามารถ...หรือไม่"这类公文腔）、
   固定人称敬语、要求同一句话用同一个说法。

### 术语表（强烈建议填）

公司名、产品名、人名一定要写进去，翻译准确度提升非常明显：

```json
"glossary": {
  "泰佳物流": "ไทยเจีย โลจิสติกส์",
  "验货": "ตรวจสอบสินค้า",
  "王总": "คุณหวัง"
},
"domain_hint": "跨境电商发货和清关的商务会议"
```

## 三、开会时怎么用

1. **先戴耳机**（重要，见下面"回声"一节）
2. 双击 `启动.bat`，字幕会在一个**独立窗口**里打开
3. 开钉钉会议
4. 在钉钉里点 **共享屏幕 → 共享窗口 → 选中这个浏览器窗口**
5. 开始说话，字幕会自动出现

### 字幕页上的按钮

### 它是一个独立窗口，不是浏览器标签页

启动时会用 Chrome（没有就用 Edge）的**应用窗口模式**打开：**没有标签栏、地址栏、
书签栏**，只有一条写着「中泰实时翻译字幕」的系统标题栏。窗口本来就只占屏幕 1/4，
这些浏览器界面会吃掉上面三分之一。

在钉钉里按普通窗口共享即可。窗口大小位置它会自己记住。

**开会前先打开「⋯ → 窗口置顶」。** 投屏共享的是这个窗口本身，被别的窗口盖住对方
就看不到字幕了。置顶后它会一直浮在最前面，你切别的窗口也不影响。选择会记住，
下次启动自动恢复。

用的是独立的浏览器配置目录 `.browser-profile`（约 55MB），
所以不带你平时的扩展和书签，也不会干扰你正在用的浏览器。

想改回普通标签页，或者不自动打开：

```json
"server": { "window_mode": "browser" }    // 或 "none"
```

### 三种开会方式，开会时现选

程序启动时**什么都不会自动开**——不连公网、不开付费模式。按这场会的情况在
`⋯` 菜单里选：

| 这场会是什么情况 | 怎么做 |
|---|---|
| 就是和泰国人聊，不用投文档 | 什么都不用开，钉钉里共享字幕窗口就行 |
| 要投 PPT / 客诉模板给对方看 | `⋯` →「🔗 分享字幕」，链接发过去，屏幕共享留给文档 |
| 重要会议，想更快 | `⋯` →「⚡ 极速模式」（按秒计费，会上实时显示花了多少） |

这两项在菜单里单独分了一组，标着「按需开启 · 平时不用」——它们和改字号、
深色模式那些不一样：一个花钱，一个对外开链接，不该长一个样。

不想要某个入口（怕误点，或者发给别人时不希望他们看到），
在 `config.json` 里关掉，菜单里连显示都不显示：

```json
"fast_enabled":  false,
"share_enabled": false
```

关掉是**服务端真的拦住**，不是把按钮藏起来。

### 🔗 分享字幕链接（不用再牺牲屏幕共享位）

以前只能在钉钉里共享**字幕窗口**，于是 PPT、客诉模板就发不出去了。

现在：`⋯` 菜单 →「🔗 分享字幕」，生成一条公网链接：

```
https://brave-otter-plum.trycloudflare.com/?k=Xk7_mQ2p
```

把链接贴进钉钉聊天，**对方在手机或第二块屏上打开就能看字幕，
你的屏幕共享继续放文档**。面板上会显示有几个人在看。

- 第一次用会自动下载 `cloudflared`（约 30MB，免账号、免注册，只下一次）
- 链接带随机口令，**每次启动重新生成**，旧链接自动失效
- **对方只能看**：暂停、极速模式、改字、清屏、生成纪要全部拦在服务端，
  不是靠界面藏按钮——藏起来只是看不见，自己拼消息照样能发
- 点「关闭分享」链接立刻失效，已连进来的人会被断开

> 你们聊的是客诉和报价，所以口令这一层是必须的。链接可能被转发，
> 开完会记得关掉分享。

### 把软件发给别人用

**最省事**：把 [Releases](../../releases/latest) 页的链接发给对方，让他自己下载最新版。
发布包是 GitHub 自动打的，只有程序本身，没有任何密钥和会议记录（发新版本的方法见 `工具/说明.txt` 末尾）。

**想把你调好的配置或术语表一起给对方**：用本机脚本打包——

```bash
.venv\Scripts\python.exe 工具\打包分发.py
```

生成一个约 140KB 的干净压缩包。**绝对不要直接压缩整个文件夹**——
里面有你的 3 把密钥和 21 份会议记录（客诉、报价、产能）。

脚本会自动剔掉密钥、会议记录、本机环境，并且**打完包再扫一遍确认没有密钥漏出去**，
发现问题就删包并报错。带上 `--带术语表` 可以把术语表和纠错表也带过去。

> **对方如果在中国大陆**：`api.anthropic.com` 直连不上，要配
> `anthropic_base_url` 指向中转地址，否则翻译一直失败。
> 所以跨国场景建议**由泰国这边跑这套软件**，总部那边看分享链接就行。

### 两档速度：平时用便宜的，重要会议开「极速」

识别有两条路，在 `⋯` 菜单里切换，**不用改配置文件**：

| | 说完之后等 | 成本 | 什么时候用 |
|---|---|---|---|
| 平时（一句话识别） | ~1.4s | ¥1.4/小时，每月免费 5000 次 | 日常例会 |
| **⚡ 极速（流式识别）** | **~0.3s** | ¥5.9/小时，**无免费额度** | 重要会议 |

极速模式是 WebSocket 双向流式：人一开口就把音频往云端送，**说的过程中文字就在回来**，
说完只剩收尾。省下来的约 1.1 秒是纯赚的——不改翻译模型、不动断句等待，
译文质量和断句行为完全不变。

**开着的时候顶栏会出现一个绿色小标**，实时显示这场用了多少分钟、花了多少钱：

```
⚡ 19.3 分钟 · ¥2.77
```

点这个小标就能关掉。**每次启动默认是关的**——忘记关会一直花钱，忘记开只是慢一点，
两种遗忘的代价不对等。

出任何问题（握手失败、网络断、超时）都会**自动退回一句话识别**，不会丢句子。

> **境外用户注意**：实时识别要单独开通「跨境」服务，否则点极速会直接提示开不了。
> 开通入口 https://console.cloud.tencent.com/asr/settings
> （开通跨境服务 + 开启后付费）。国内用户不受影响，每月还有 5 小时免费。

### 会议结束后记得按「暂停」

程序一旦启动就一直在听。会开完了你在翻记录、旁边同事在聊天、或者放个视频，
麦克风照收，一句句识别加翻译，**钱就这么流走了**。

顶栏左边第一个按钮就是「暂停」（快捷键 `P`）。按下之后：

- 不断句、不识别、不翻译，**一次调用都不产生**
- 正在攒的半句、排队等识别的句子，全部丢掉——不会在你按「继续」时突然蹦出来
- 整个页面变暗 + 顶部一条橙色横幅「⏸ 已暂停」。投屏时对面一眼就知道是停了，不是坏了

退出程序时终端会告诉你这场停了多久：

```
[用量] 本场暂停了 23.5 分钟，这段时间没有任何识别和翻译调用
```

中途要跟旁边同事单独说几句话、又不想打断对方那一路，用顶栏的
「🎤 我方 / 🔊 对方」单独关一路就行，不用整个暂停。

### 最新的一句在最上面

新消息直接占据固定位置，旧的往下推——视线不用追着滚动条跑。这是为
「字幕窗口只占屏幕 1/4、旁边还在共享文件」这种场景设计的。
想改回传统的从上往下，在「⋯」菜单里关掉「最新在上」。

界面默认浅色。深色、紧凑、隐藏原文、字号都在「⋯」菜单里，选择记在本机。

整个过程都有反馈，不会让人干等：

1. **开口约 2 秒后**，顶部出现一条灰色的「正在说话」实时行，文字随着你说话不断延长，
   还会自我修正（"下课院"→"下个月"）。这是 tiny 模型跑的**中间结果，会有错字**，
   只是让人看到系统在听。
2. 说完约 5~6 秒，正式原文出现在字幕区，中间结果消失。
3. 译文**一边翻一边往外冒**（像打字），末尾带光标表示还在写。

中间结果只用空闲算力跑——正式识别一忙就自动让路，绝不会拖慢真正要用的那份译文
（实测开启前后，正式识别耗时 5.9s vs 6.1s，基本无差别）。

嫌它乱就关掉：`"asr": { "partial_results": false }`

每条字幕右边的 `+5.2s` 是这句话"说完到出字幕"的实际耗时，黄色偏慢、红色说明积压了。

| 按钮 | 作用 |
|---|---|
| **暂停 / 继续** (快捷键 `P`) | 顶栏左边第一个。暂停期间不识别、不翻译，**不产生任何调用** |
| **大字幕** (快捷键 `F`) | 只显示最新一句，超大字体，投屏效果最好 |
| **A− / A＋** | 调字号 |
| **🔈 朗读** | 用电脑语音把译文念出来（需要系统装了泰语语音包） |
| **🎤 我方 / 🔊 对方** | 临时关掉某一路（比如你要跟旁边同事说句话） |
| **生成会议纪要** (快捷键 `M`) | 把这场会整理成中泰双语纪要，同时生成 Word |
| **清屏** | 清空字幕 |
| **全屏** | 浏览器全屏 |

## 三点五、会议记录

每场会议自动存一份到 **`会议记录`** 文件夹，按开始时间命名：

```
会议记录/
  2026-09-14_1021.md      给人看的：时间、说话人、原文、译文
  2026-09-14_1021.jsonl   给程序读的：一行一句，方便检索或统计
```

`.md` 长这样：

```markdown
### 16:01:13　**对方**　中文 → ไทย

> 10月2号到13号会有一个验厂。

วันที่ 2 ถึง 13 ตุลาคม จะมีการตรวจโรงงานครับ
```

**每句翻完就写盘**（最多滞后 3 秒），所以哪怕直接关掉窗口、程序崩了，
记录也只会丢最后几秒。**手动改过的句子会重写对应那行**，文件里始终是修正后的版本，
并标上「✏️已手动修正」。

全部保存在本机，不会上传。涉密会议关掉它：

```json
"save_transcript": false
```

## 三点六、自动生成会议纪要

开完会在「⋯」菜单里点 **生成会议纪要**（或按 `M`），几十秒后
`会议记录` 文件夹里会多出两个文件：

```
2026-09-16_1003_纪要.md      Markdown
2026-09-16_1003_纪要.docx    Word，泰文字体已经设好，直接能发出去
```

纪要是中泰双语对照的，包含：会议信息 / 议题与结论 / **待办事项表格** /
需要确认的事项。长会（两小时以上）会先分段提要再合成，多花一两分钟。

也可以事后在命令行补生成：

```bash
.venv\Scripts\python main.py --minutes
```

不带参数就整理最近一场；要指定某一场就把 `.jsonl` 的路径跟在后面。

想每次退出程序时自动生成一份：

```json
"auto_minutes": true
```

**它只写字幕里真实出现过的内容。** 人名、日期、数字、负责人一律不允许编造，
说得不清楚的地方会写「待确认」而不是替你填一个看着合理的值——
纪要是拿去分派工作的，编一条比漏一条危害大得多。
所以拿到纪要后，**关键数字和日期还是要和对方口头核对一遍**。

## 五、常见问题

### ✗ 对方说话没有字幕

1. 跑 `--test-audio`，看「对方」那一路有没有电平跳动
2. 确认钉钉的声音是从**默认扬声器**出来的（Windows 设置 → 系统 → 声音 → 检查默认输出设备）
3. 如果你插了耳机/外接显示器音响，默认输出设备变了，跑 `--list-devices` 找到对应的 `系统声音` 设备序号，填进：
   ```json
   "audio": { "loopback_device_index": 12 }
   ```

### ✗ 一个会里有中国人也有泰国人，「对方」该锁成什么？

先分清楚：**「对方」不是一个人，是一条音频通道**。

```
我方 = 麦克风       → 你，以及任何坐在你旁边的人
对方 = 系统声音环回  → 钉钉里传过来的所有远端的人，混在一起
```

所以该锁什么，取决于谁在你房间里、谁在远端：

| 坐法 | 我方 | 对方 |
|---|---|---|
| 泰国人坐你旁边，中国人在钉钉 | **自动** | 锁 **中文** |
| 中国人坐你旁边，泰国人在钉钉 | 锁 **中文** | 锁 **泰语** |
| 两个人都在钉钉里 | 锁 **中文** | **自动** |

**能锁就锁。** 锁定是 100% 可靠的；自动判定在短句上会出错，而且**每判错一次就要多打一次云端往返**——实测对方那一路开自动时每句 1.34 次调用、延迟中位 1.9 秒，锁定时是 1.14 次、0.9 秒。

两个远端的人会混成同一个「对方」，程序分不出谁是谁（没有声纹分离）。
但如果他们说不同语言，语种标签就等于在告诉你是谁。

### ✗ 对方说话时，"我方"也冒出同样一句

你在用外放，麦克风把音箱里对方的声音又录了一遍。**戴耳机能彻底解决。**

不戴耳机也有一道防线：程序会把麦克风收到的每一句和**同一时刻音箱在放的内容**
做能量包络互相关，波形对得上就判为回声丢掉。合成场景实测拦截率 93~98%，
把用户自己说的话误丢的比例为 0。

它的原则是**宁可放过、绝不错杀**：拿不准一律保留。所以偶尔还会漏一两条重复，
那是故意的——丢掉你自己说的话，比多出一条重复字幕严重得多。

**拿不准它在你的环境里准不准，先用观察模式开十分钟会：**

```json
"echo_cancel": { "mode": "observe" }
```

这个模式下判定照跑、一句都不丢，终端会把"本来会被丢掉"和识别出来的文字一起印出来：

```
[回声·观察] 这一句本来会被当成回声丢掉（相关 0.98／覆盖 100%／偏移 -160ms）
           识别结果：然后第46项是咱们火灾预防和扑救计划
```

印出来的**是对方刚说过的话 = 判对了**，改回 `"mode": "on"`；
**是你自己说的 = 会误伤**，直接关掉：

```json
"echo_cancel": { "enabled": false }
```

关掉之后行为和加这个功能之前完全一样（自检里有专门一条在验这个）。

### ✗ "嗯""好的"这类词也占字幕、还要等翻译

已经处理了：纯语气词（嗯/啊/哦/อืม/เอ่อ…）直接不出字幕；
"好的""收到""ครับ""ไม่มี"这类常用短句查表秒回，0 毫秒、不走模型。
真实会议记录实测，这两类占 6%，一场两小时的会省下约 74 秒干等和 50 次调用。

词表在 `translator/quick.py`，可以自己往里加。不想要就关掉：

```json
"drop_fillers": false,
"quick_replies": false
```

### ✗ 有些词老是翻不准

**在会上直接点那条字幕改字**——改完会重新翻译，同时记两个地方：

- 终端和运行日志：`[纠错] 厌厂 → 验厂`
- `会议记录\纠错记录.txt`：专门攒这些，攒一批之后一次性补进 `config.json`

```
2026-09-16 17:47
  听成： 厌厂
  应为： 验厂
```

补的时候分两类：

| 情况 | 补到哪 | 效果 |
|---|---|---|
| 识别老听错的词（厌厂→验厂） | `asr_corrections` | 翻译前确定性替换，不靠模型猜 |
| 译法要统一的专业词、人名、公司名 | `glossary` | 告诉模型这个词固定怎么译 |

两个表都塞在系统提示里，而系统提示走缓存，**加词不增加任何延迟**。

### ✗ 有些字幕是灰色小字，写着「无实质内容」

那是识别把噪音听成了词（比如泰语识别出 `อี`、`โป` 这种单音节碎片），
模型判定没有可翻的内容。这类实测占 5% 左右，全删掉怕你以为程序丢字了，
所以缩成一行灰字留着——原文还在，但不占地方。整块都是这种时连时间戳那行一起收起来，
大字幕模式下完全不显示。

### ✗ 开场头几句是乱码，之后才正常

多半是**上一场会的语种锁定还留着**：跟国内总部开会时把「对方」锁成了中文，
这次换成跟泰国同事开，开头几句泰语就被硬塞进中文引擎，出来一串不知所云的汉字。

顶栏「对方」旁边那个语言标点一下就能改（自动 → 中文 → 泰语循环），
**改完会自动存进 `config.json`，下次启动还是这个设置**，不用每次重设。
终端会回一句「已记住，下次启动仍是「泰语」」。

多人会议里一边混着中文和泰语时，那一路就设成「自动」。

### ✗ 识别到一堆没人说的乱码

背景噪音太大。把 `config.json` 里这两个值调高：

```json
"vad": { "aggressiveness": 3, "rms_threshold": 0.012 }
```

### 换成 OpenAI 试试（识别和翻译都能换）

两条路各自独立，可以只换一条，也可以都换。**Key 填一个地方就行**，识别和翻译共用：

```json
"openai_api_key": "sk-…",
"translate_backend": "openai",
"openai_translate_model": "gpt-4o-mini",
"asr": { "backend": "openai", "openai_model": "gpt-4o-mini-transcribe" }
```

改回来把 `translate_backend` 写成 `anthropic`、`asr.backend` 写成 `tencent` 即可。

测一下两边差多少：

```bash
.venv\Scripts\python.exe 工具\试试OpenAI.py
```

拿你自己会议记录里的句子测，提示词和术语表两边完全一样，比的是模型本身。
重点看**首字时间**——字幕是边翻边冒的，首字出来人就不觉得卡了。
加 `--录音` 可以连语音识别也一起比（要对着麦克风说一句中文）。

几个坑已经在代码里处理了：

- `gpt-4o-transcribe` / `gpt-4o-mini-transcribe` **不支持 `verbose_json`**，
  会按模型名自动换成 `json`（`whisper-1` 才用 `verbose_json`）
- `whisper-1` 是老模型，慢；要快就用 `gpt-4o-mini-transcribe`
- 术语表会自动拼成识别提示喂给模型，专业词和人名认得准很多
- `gpt-5` / `o` 系列要用 `max_completion_tokens` 且不能传 `temperature`，已按模型名自动切换

### ✗ 字幕出得太慢

先看字幕右边的 **`+X.Xs`**，那是"说完到出字幕"的实际耗时。黄色偏慢，红色说明已经积压。

正常情况的时间构成：

```
0.72s  断句（等你真的说完）
5.0s   语音识别  ← 瓶颈，占 80%
0.5s   翻译首字开始往外冒
1.5s   翻译完成
```

**不要去调小 `end_frames`。** Whisper 内部固定按 30 秒窗口处理，2 秒的音频和
8 秒的识别耗时几乎一样，所以句子切得越碎，总开销越大、排队越久。宁可多等 0.2 秒
让短句合并，整体反而更快。这一条实测过，反直觉但确实如此。

能调的：
- 翻译换成 Haiku：`"model": "claude-haiku-4-5"`（比 Sonnet 快约 35%、便宜一半，
  但短句措辞偶尔偏生硬。当前默认是 `claude-sonnet-5`）
- 噪音多的话调高 `vad.rms_threshold`，减少无效句子占用识别时间
- 真要突破 5 秒那道坎，只能换云端识别（见上面的方案 A）

### ✗ 字幕落后越来越多

程序会自动丢弃排队超过 6 秒的句子（终端里会打印"积压 X 秒，丢弃一句"），
所以延迟不会无限增长，代价是漏掉几句。想更激进就调小 `max_lag_sec`。

### ✗ 对方说泰语，却被当成中文翻成了泰语

已修复。原因是强制指定语言后，Whisper 会把泰语硬写成汉字音译（"阿斯瓦迪尚"），
而"看字形判语种"这道校验会被架空。现在由 `tiny` 模型先判语种，再按声道先验
（麦克风偏中文、系统声音偏泰语）加权修正。

先验只是加权不是锁死——对方改说中文照样认得出。不想偏向就把 `language_bias`
里对应的值改成 `null`。

### ✗ 一句话被从中间切断

对方说话停顿多。调大：`"vad": { "end_frames": 30 }`（约 900ms 才算说完）

### ✗ 泰语字幕显示成方块

Windows 缺泰语字体：设置 → 时间和语言 → 语言和区域 → 添加语言 → ไทย（只装「基本键入」即可）
